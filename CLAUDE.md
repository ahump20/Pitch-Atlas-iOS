# CLAUDE.md — Pitch Atlas iOS

Guidance for Claude Code working in this repository.

## What this is

Native SwiftUI iPhone app for **Pitch Atlas** — a sourced, interactive reference for how pitches are gripped and thrown. **Independent, standalone product.** It has no relationship to any other brand or product; no outside brand name, mark, identity, or account appears anywhere in the app or this repo. The web companion is `pitch-atlas.com` (`ahump20/Pitch-Atlas`).

- iOS 17.0 deployment floor. Swift (language version pinned in `project.yml`).
- Bundle ID: `com.pitchatlas.app`. Signing team is configured locally / in CI, not committed.
- The project file is **generated by XcodeGen** from `project.yml` — never hand-edit `PitchAtlas.xcodeproj` (it's gitignored). Change `project.yml`, run `xcodegen generate`.

## Non-negotiable doctrine (ported from the web repo)

- **Sourced, not corrected.** Every claim wears its source and confidence tier. A measured Statcast figure and a beat-writer quote never share a tier color. An unverified claim shows *as* unverified, with its required note — never hidden, never upgraded.
- **No mock data, no fabrication.** No `Math.random`, no placeholder arrays, no invented spin/velo. The grip photos carry "not tracked data." If a real source can't be determined, stop and ask.
- **No fabricated freshness.** Every "as of" computes from a real `retrievedAt`. No hardcoded "Updated today"/"Live".
- **Four states on every data surface.** loading (source-tagged skeleton) / error (a reason — the seal + alt-text tile, never a blank box) / empty (a reason) / populated (data + source + tier dot).
- **Rights-first images.** The visual actor is the seam specimen or first-party grip photography. No agency/player photos, no team/league marks, no re-hosted third-party footage.
- **Done = visitor-verified.** "Build succeeded" is not proof. Run it on the simulator/device and confirm what a user sees. For the offline promise, test in airplane mode on first launch.

## Content source of truth

The content lives in the **web repo** and is generated into `PitchAtlas/Resources/Content/*.json` by `tools/generate-content`. Never hand-author content JSON in this repo. The generator's drift guard reads expected record counts **from source at generate time** — never hardcode counts.

**Which web repo:** `github.com/ahump20/Pitch-Atlas` @ `main`. The generator resolves a sibling of this repo (`../../../Pitch-Atlas` from `tools/generate-content/`, i.e. `~/Pitch-Atlas`) unless `PITCH_ATLAS_WEB` overrides it. Trust that resolution, not a path written here.

## Architecture

Native SwiftUI: tab shell, searchable index, grip library, craftsmen hall, sources browser, and `SeamBall` specimens. State via `@Observable` + `@Environment` DI (no `ObservableObject`/Combine). Navigation: 5-tab `TabView` + per-tab `NavigationStack` + a `DeepLinkRouter` for `pitchatlas://` routes. The offline Three.js/WebView island is a later plan; it is not part of the binary. The Blaze companion rides each tab's scroll via a shared `BlazeCompanionController` injected by `TabScaffold` (the common ancestor of the scroll and the bottom-inset companion).

## Shipped scope (community is in the binary)

The binary is **no longer reference-only**. It ships the **Supabase community layer**, **anonymous-first** since 1.1.0: contributing (field notes, discussion, reports, blocks) needs no sign-in — `AuthSessionStore.ensureSessionForWrite()` mints an anonymous account lazily on the first write and is the app's ONLY mint site (reads never mint; mirror of the web's `community.read-path.test.ts` contract). Sign in with Apple (`linkIdentityWithIdToken`) or an email claim (`updateUser(email:)`) upgrades the record in place — the user id is preserved, so posts ride along; a magic link is refused for an anonymous session because it would orphan the record. Image uploads require a claimed account (server policy). UGC-moderation pillars: report, block, a 17+ age gate, guidelines/media-terms acceptance (1.2), in-app account deletion (5.1.1(v)) for anonymous and claimed accounts alike. Reachable via Atlas → "Account and Safety". The reference manual (index, grips, craftsmen, sources, filed specimens) stays fully usable with no session. iPhone only. See `docs/COMPLIANCE.md` and `docs/APP-REVIEW-NOTES.md`.

**Resolved (was an open item):** blocked-user content hiding is enforced client-side too. `CommunityVisibility` filters blocked authors out of both community tabs, hydration is fail-closed (a failed block-list load sets both tabs to `.failed` rather than showing unfiltered content), and the blocked-contributors manager lives in Account & Safety — covered by `testBlockedContributorVisibilityFiltersCommunityRowsLocally`. Supabase RLS remains the server-side backstop.

## Build / release

```bash
xcodegen generate
./scripts/build.sh            # iPhone simulator build
./scripts/build.sh test       # build + test
```

The `PitchAtlasReleaseGate` scheme (target `PitchAtlasReleaseGateUITests`) is a
manual pre-archive gate that drives the real UI against production Supabase —
anonymous post end to end. It is intentionally NOT in the `PitchAtlas` scheme:
CI must never run it. Server write access is column-scoped per table; insert
payloads must encode only granted columns (ids are server-generated, read back
via RETURNING) — pinned by `testInsertPayloadsStayInsideColumnScopedInsertGrants`.

CI is **Xcode Cloud** (configured in the Xcode project). Three release rules: build numbers are monotonic per app and bump in lockstep across configs; an `action_required` result means a compile error, not an approval gate; release branches merge back to `main` the same day they archive. The post-clone step generates the Xcode project. Content refresh is a local pre-release step that must be committed before archive.
