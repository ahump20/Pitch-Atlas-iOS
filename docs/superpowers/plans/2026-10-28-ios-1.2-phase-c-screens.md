# iOS 1.2 Phase C — Existing Screens to Web Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every screen the app already has reads like the same page on pitch-atlas.com at 440pt: same sections in the same order, same words, same tokens, each one checked against a screenshot pair.

**Architecture:** Screens stay native SwiftUI on the Plan 1 tokens and the Plan 2 kit (buttons, cards, wall, binder, card back). Shared pieces the web repeats across pages (the chapter mark with the Muybridge pitcher, the site footer with its rotating quote) are built once in `Components/`. Pure, testable logic (which three specimens the wall shows, which quote a screen shows, the registry's "as of" line, the chapter mark's plate frames) lives in small value types beside the views and is pinned by XCTest against the web's own values. Each task ends with a screenshot run (`shots/<stop>/…` branch → `.github/workflows/screenshots.yml`) and a written pair review.

**Tech Stack:** SwiftUI (iOS 17.0 floor), XcodeGen, XCTest/XCUITest, GitHub Actions (macos-latest, iPhone 17 Pro Max simulator; ubuntu + Playwright for the site).

**Spec:** `docs/superpowers/specs/2026-10-05-ios-web-parity-design.md` with its 2026-10-27 addendum; master plan `~/.claude/plans/is-users-austinhumphrey-pitch-atlas-ios-memoized-pebble.md` §5 (screens). Release plan: `docs/superpowers/plans/2026-10-27-ios-1.2-parity-release.md` (Phase C).

## Global Constraints

- iOS 17.0 floor: no MeshGradient, ScrollPosition, onScrollGeometryChange, scrollTransition-only effects without fallbacks. `SWIFT_VERSION "5.0"` (no bare regex literals).
- No color literals outside `PitchAtlas/Core/Theme/` (`scripts/check-no-color-literals.sh`). Colors come from `PitchAtlasTheme`/`WebTokens`.
- Project changes go through `project.yml` + `xcodegen generate -q`; never hand-edit the project.
- Content is generated (`tools/generate-content`, `PITCH_ATLAS_WEB=<fresh clone>`); never hand-author content JSON. Copy that the web hard-codes in a component (section titles, ledes, CTAs) is ported verbatim into the Swift view, with the web file named in a comment.
- No mock data, no invented numbers, no fabricated freshness: every "as of" computes from a real `retrievedAt`.
- Four states on every data surface (loading with a source-tagged skeleton, error with a reason, empty with a reason, populated with source + tier).
- 44pt tap floor; Dynamic Type; VoiceOver labels; Reduce Motion lands every animation on its final frame.
- "sourced, not corrected" appears nowhere. No outside brand anywhere in the app.
- Account and Safety stays reachable from Atlas in one tap (App Review path).
- Commits: `type(scope): description`, ending with the session's Co-Authored-By and Claude-Session lines.
