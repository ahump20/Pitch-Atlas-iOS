## Decisions I'm making (and disagreements I'm naming)

1. **Live site beats the Oct 5 spec.** The spec gets a dated addendum in Phase 0 listing what changed on the web and the call for each item below.
2. **New web features — calls:**
   | Web feature | 1.2.0 call |
   |---|---|
   | Master-file notes, field-notes outage copy, shape map from the pitcher's view, Support page | **Ship** (content + small screen changes) |
   | Flight Lab | **Ship the flat schematic** natively, driven by a Swift port of `src/lib/slowpitch` with its tests ported; the 3D stage is a named fast-follow |

   Anything else that would ship rough becomes a named fast-follow in the report, not a half-built screen.

5. **Store copy** comes from the live site's lines and Austin's own words. No "sourced, not corrected." Not written by a voice/writing tool — Austin's rule ("listen to what i actually say") wins over any tool that offers to write it.
6. **Out of scope:** the web docs-and-bugs PR from the old master plan §8 (listed as a follow-up only). App preview videos (none exist today; "preview photos" = screenshots).
7. **Execution:** inline in this session (executing-plans), in the existing `~/Pitch-Atlas-iOS-parity` worktree, one fresh whole-branch review on the most capable model before merge. Each phase gets its own short plan doc under `docs/superpowers/plans/` and ledger under `.superpowers/sdd/`.
